# Memory Writing

メモリへの書き込みは、ユーザーが明示的に依頼した場合、または現在のワークフローで記録先と記録行為が明確に承認されている場合だけ行う。レビュー、調査、診断など read-only の依頼ではメモリを変更しない。

Codex のメモリ更新はユーザーの明示依頼がある場合に限り、`~/.codex/memories/extensions/ad_hoc/notes/` に小さな更新ノートを追加する。`~/.codex/memories/MEMORY.md`、`~/.codex/memories/memory_summary.md`、`~/.codex/memories/rollout_summaries/` は直接編集しない。

## 書き方ルール

- **正解 if-then だけを書く**。「○○と間違えた」「最初は××だった」等の失敗ナレーションは書かない。失敗内容を文章として残すと未来の attention が失敗側に歪んで再発を呼ぶ
- 形式: `if <状況> then <行動>` の表 or 短い参照リスト
- 既知パラメータ(パス・コマンド・URL・閾値)はリテラルで書く
- 適切に**抽象化**する。プロジェクト固有でない学びはより汎化された if-then に
- 訂正/失敗ログ/反省文セクションは作らない

## 記録候補

承認された記録ワークフローでは、以下を学びの候補として扱う:

- ユーザーから訂正・叱責を受けた
- 自分の実装/出力ミスに気づいた
- 環境(設定ファイルパス・CLI フラグ・API挙動)の正解を新たに把握した
- 3rd party tool の status / 仕様を確認できた
- セッション終了時に再利用価値のある学びがある

## 既存メモリの保守

既存メモリの保守も、ユーザーが明示的に依頼した場合、または承認済みの記録ワークフローの範囲内でのみ行う。過去 memory に失敗ナレーションが含まれていたら:
1. 正解 if-then だけ抽出
2. 失敗説明部分を削除
3. タイトル・description も「失敗○○」→「正解○○」に書き換え

詳細は各プロジェクトの `memory/feedback_memory_writing_style.md` (存在する場合) を参照。無い場合は本ルールに従う。
