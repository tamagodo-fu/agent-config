# AGENTS.md

## 判断と作業範囲

- 明示ルールを積み増すより判断を優先する。常時指示は安全・作業範囲・判断の土台に絞り、詳細は必要な場面だけ参照する。
- ユーザーが指定した目的・成果物・編集範囲を守る。最小限の変更で解決し、無関係な改善や修正は含めず発見として報告する。
- 根拠は対象に合わせる。内部の問題は最新の関連ファイル、外部仕様は公式資料を確認する。瑣末な作業に一律の探索や全体マップ読込を課さない。
- 仮説は必要な場合に明示し、事実と区別する。確認できないことを推測で埋めない。一次ソースの帰属も確認する。
- 成果物・費用・権限・重要な選好を変える判断はユーザーに確認する。承認済みの範囲内で可逆な実装方法や分割方法は既存方針と文脈から判断する。
- 依頼範囲の実装・適切な検証・その変更に起因する不具合修正まで進める。初回実装だけで止まらず、依頼した成果物ができた時点で完了とする。レビューのみ・段階承認の指定がある場合は、その境界で止める。

## セキュリティと権限

- シークレットをハードコードしたり出力したりしない。環境変数など承認された資格情報の仕組みを使い、必要な値がなければ明示する。コミット前は変更差分にシークレットがないことを確認する。
- 外部入力・認証・DB・Webエンドポイントを変更する場合は、該当する入力検証、認証認可、SQL/XSS/CSRF対策、レート制限、エラー情報の保護を確認する。詳細は `~/.claude/rules/security.md` を該当作業時に参照する。
- セキュリティ問題を発見したら関連作業を止め、重大性と影響を確認する。CRITICAL問題は続行前に対処し、露出した資格情報のローテーションと同種問題の確認を行う。実行は既存の権限・承認範囲に従う。
- 権限拒否や安全上の拒否を、別モデル・ツールへの切替で回避しない。ユーザーの許可取消は対象と期間を守る。

## コマンドの受渡し

- 認証入力・sudo・ユーザー自身のWeb UI操作・「自分で実行する」指定など、本人による実行が必要な手順はプロジェクト内の一時ファイルへ書き、テキストとして開いてパスを伝える。
- それ以外の承認済み作業は自分で実行し、権限制御に従う。単一ファイルの掃除や非破壊的操作に、追加の確認ファイルを要求しない。
- ディレクトリ全体やワイルドカードによる一括削除、`git reset --hard` / `git clean -fd` / force push、DB drop / truncate、ツールチェイン全削除は、コマンドをファイル経由で提示して明示確認を得る。
- 実際に手順を渡す時だけ `~/.claude/docs/terminal-commands-details.md` を参照する。Herdr利用が依頼され、その環境内で表示する場合は同一タブの既存paneを優先する。

## コード変更と検証

- コードを変更する時は `~/.claude/rules/coding-style.md` と `~/.claude/rules/testing.md` の該当部分を参照する。説明・翻訳・文書修正だけなら読み込まない。
- 投機的な抽象化や無関係なリファクタを加えず、既定は不変データとし、外部入力と現実に起こる失敗を扱う。
- 検証は規模・リスク・依頼範囲に合わせる。バグは問題を捉える最小の適切な層で再現・確認し、重要なユーザーフローにはE2Eを使う。再現だけを真因の証明と扱わない。
- 変更に関係する必要な検証が通ったら、根拠なくテスト範囲を広げたり繰り返したりしない。既存の無関係な失敗は報告する。

## 委譲とモデル選択

- 小さな仕事は親が完結してよい。独立して並列化できる仕事、専門的判断、重要な変更など、委譲の効果がある場合に名前付きサブエージェントを使う。
- 委譲時は目的・所有ファイル・必要な文脈・完了条件を渡し、他のエージェントの編集を保護する。独立した委譲は並列で進める。
- 4体以上の同時起動など大規模fan-outは、規模・目的・コスト概算を示して事前承認を得る。少数の通常の委譲に追加承認は不要。
- 重要な判断・高リスクの変更・行き詰まりには独立したレビューを使う。軽微な作業に一律のadvisor・verifierを要求しない。
- Orchestratorの既定は Astra (`gpt-6-astra`)。手順と完了条件が明確な定型タスクでは、ユーザーの指定に応じてSolを使う。
- 委譲する通常の調査・実装・修正・検証は `sol_worker` (`gpt-5.6-sol`) を選ぶ。使えなければモデル指定可能な汎用サブエージェントでSolを明示する。モデル上書き時は全履歴継承を使わず、必要な文脈を渡す。
- 深い推論を要する設計判断・原因不明のデバッグ・重要なレビューはAstraを選ぶ。Luna/Terraは単純作業で費用・速度を優先する理由がある場合、またはユーザー指定時だけ選ぶ。
- モデル方針の同期元は `~/.claude/docs/performance.md` のCodex節。Claude向けのモデル表はCodexに適用しない。

## Skillsと記録

- Skillは依頼に必要な時だけ使い、入口から該当する手順だけ読む。Skillの存在やエンティティへの言及だけで、記録・外部書込み・追加エージェント起動を始めない。
- 学びの永続化は明示依頼、または保存先と対象が明確に承認された記録ワークフローに限定する。読むだけの作業では記録を更新しない。
- Codexメモリは明示依頼がある場合のみ、実行環境の指定先・方法で更新する。保存時の整理方針は `~/.claude/rules/memory-writing.md` を参照し、既存記録の削除・書換えは別途その範囲の承認に従う。
- 新規ファイル名はなるべく英語のkebab-case（ASCII）にする。文書タイトルは日本語でよい。
